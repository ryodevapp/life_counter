# LifeCounter v1.1 実装計画(効率重視の改訂版)

## Context

出荷済みの v1.0.2(`main` = c8a1fd7)を土台に、ブランチ `feature/v1.1` で v1.1.0 を作る。設計は `design/specs/2026-10-15-v1.1-design.md`(本人 OK 済み・push 済み)。下書きの計画 `design/plans/2026-10-15-v1.1.md`(未コミット)を、**手戻りの少なさ・並行化・危険の先回り**で組み直したのがこの計画。実装の後、この内容で `design/plans/2026-10-15-v1.1.md` を上書きしてコミットする。

作るもの: 今日の問い(365問・1年で1巡・スタンプ5つ・話す/書く欄1つ・1年前の答え)、やりたいことリスト、ウィジェット(小=人生◯日目だけ/中=問い+スタンプだけ)、朝の通知の日付ごとの予約、記録の画面の対応、記録の書き出し。

## 下書きからの主な直し(調べて分かった事実)

- Isar のスキーマ登録は `lib/main.dart:21`(`isar_provider.dart` ではない)
- `home_widget` 0.10 の pod は **iOS 14 以上**。Runner は 13.0、Podfile は 16.0 で食い違っている → **Runner を 14.0 に上げる**(iOS 13 の機種はすべて 15 まで上げられるので締め出しは起きない)。**ウィジェット拡張だけ 17.0**。v2.0 の「全 Pod を 17.0 にする」post_install は持ってこない
- App Group の UserDefaults は申告が要る API → `PrivacyInfo.xcprivacy`(理由 1C8F.1)を Runner と拡張に置く
- 通知の再予約は1か所にまとめる: `main_tab_view.dart` で起動時・`ref.listen(userSettingsProvider)`・前面に戻ったときに `NotificationService.refresh`。マイページで時刻を変えても予約し直さない今の不具合もこれで直る。更新した端末に残る id 0 も消す
- 保存は「画面に出している日付」で行う(真夜中をまたいでも前日の問いに付く)
- ウィジェット用のデータは通知と同じ **60日分**(14日だと2週間開かないと空になる)
- `morningQuestionId` は v1.0.2 では書かれていない → 25問の id は残すが、過去の答えとのつながりは無い
- `record_detail_page.dart` の8つの controller(古い欄の編集)は書き直さず、新しい表示を足すだけ
- v2.0 の `WidgetPreview` と `SceneDelegate` の差分は持ってこない

## 進め方

### 段階0: 危険を先に片付ける(並行)

- 拡張ターゲット `LifeWidget`(Bundle ID `com.lifecounter.lifeCounter.LifeWidget`、iOS 17.0、App Group `group.com.lifecounter.lifeCounter`)。v2.0 の `FamilyWidget` の pbxproj の設定を手本に、「Embed Foundation Extensions」を「Thin Binary」より前に置く。まずは中身が固定の小ウィジェットだけ
- `Info.plist`: マイク・音声認識の説明文、`ITSAppUsesNonExemptEncryption = false`。`PrivacyInfo.xcprivacy` を2か所

**0-C 365問(サブエージェント・コードと独立)**

### 段階1: 画面と通知(0-B・0-C のあと、並行)

- **今日の画面**: `today_question_card.dart`(問い→スタンプ→欄+マイク→1年前→「やりたいことリストに入れる」)、`voice_input_button.dart`(`ja_JP`・端末の中で文字にする・断られても落ちない)、`today_page.dart` の4つの欄を置き換える(YOUR LIFE と偉人の言葉は残す)。今の「2秒の無入力・フォーカス外れ・裏に回ったら保存」の流れを答える欄にも使う。日付は `todayDateProvider` で持ち、前面に戻ったときと0時に切り替える
- **通知**: `morning_schedule.dart` の純粋関数 `buildMorningSchedule`(60件、id 100〜159、`人生 12,345日目` + その日の問い)と `NotificationService.refresh`。`presentBadge: false`。`onboarding_page.dart` の固定5問を外す
- **記録・リスト・書き出し**: 記録のカレンダーにスタンプ、詳細に問い・スタンプ・答え(古い欄はそのまま)。`life_tab_page.dart` の大切な人の下に `BucketSection`(できたものも薄くして残す、空のときは「思いついたら、ここに残せます」)。マイページに「記録を書き出す」(`exportRecordsAsText` → 共有シート)
- 検証: 各テスト(スタンプの取り消し・1年前の表示・連続日数の文が無い・60件の予約・新旧の記録の表示・書き出しの順番)、`flutter analyze`

### 段階2: ウィジェットの中身

- `widget_sync.dart`: `buildWidgetPayload`(60日分 `{date, lifeDays, questionId, question, stampId}`)、`update`、`importPending`(同じ日はアプリの `updatedAt` と比べて新しいほうを残す。比べる処理は純粋関数 `resolveStamp` に切り出してテスト)
- Swift: 中ウィジェット(問い+スタンプ5つ、iOS 17 の AppIntent)。押したら待ちの一覧に入れて、すぐに描き直す。0時に次の日へ切り替わるタイムライン。押したもの以外は薄く。日付・アプリ名・件数は載せない。明るい画面と暗い画面
- `main_tab_view.dart` で起動時と前面に戻ったときに `importPending` → `update`
- 検証: `flutter test`、シミュレーターでスタンプを押してアプリに反映されるか、スクリーンショットで見た目

### 段階3: リファクタリング(機能がそろってから、レビューの前に)

レビューする人が最終の形を見られるように、先に整える。**振る舞いは変えない**(テストを変えずに全部通ることが条件)。
- 消す: 使われなくなった `question_selector.dart`・`coaching_questions.json`(25問は `questions_v2.json` に移済み)・`onboarding_page.dart` の固定5問・`scheduleMorningNotification`
- まとめる: 「日付だけにする」処理(`DateTime(y, m, d)` があちこちにある)を `lib/utils/date_only.dart` の1か所に。今日の画面の「2秒待って保存」を小さな部品に切り出す
- 小さくする: `today_page.dart` は組み立てだけにし、状態は `today_provider.dart` に寄せる。1ファイルが300行を超えたら役目で分ける
- 名前と置き場所を既存の作り(`views/<タブ>/`・`services/`・`repositories/`)に合わせる
- 検証: `flutter analyze` で警告0、`flutter test` 全部 PASS、`flutter build ios --simulator --no-codesign`

### 段階4: 独立したレビューと修正

書いた本人(私)とは別のエージェントを、**最も強いモデルで2つ同時に**、読むだけで走らせる。ブランチ全体(`main...feature/v1.1`)が対象。

- **セキュリティのレビュー**(観点):
  - ウィジェットと共有する App Group に、答えの文など個人的な内容を入れていない(問い・日数・スタンプだけ)
  - ウィジェットから受け取る JSON を壊れていても安全に読む(型の確認、件数の上限、日付の範囲)
  - 声の入力が端末の中だけで処理される設定になっている。マイクの許可を断っても落ちない
  - 通知の本文(ロック画面に出る)に、答えなどの個人的な内容が入らない
  - 書き出しは利用者が共有シートで選んだ先にだけ渡る。一時ファイルを残さない
  - 新しく足した依存(home_widget・speech_to_text・share_plus)の版と、余計な権限を求めていないか。`PrivacyInfo.xcprivacy` と `Info.plist` の申告が実際の使い方と合っている
  - 秘密の情報(鍵・トークン)をリポジトリに入れていない
- **コードのレビュー**(観点): 設計書との食い違い、真夜中・うるう年・更新した端末で壊れるところ、ウィジェットとアプリの同時の書き込み、Isar の読み書きの誤り、メモリや購読の後始末、テストの抜け、読みにくさ
- 各レビューは、指摘を重い順に、場所(ファイル:行)・何が起きるか・直し方で返す
- **修正**: 私が直す(重いものから全部。直さないものは理由を書く)。直したら同じレビュー役にもう一度当てて、直っていることを確かめる。`flutter analyze`・`flutter test`・ビルドをもう一度通す

- **各段階の終わりの条件**: `flutter analyze` でエラー0、`flutter test` 全部 PASS、その段階の検証が済んでいる。満たしたらコミットして push(末尾に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`)。この Mac にだけある状態を残さない

## 本人の実機確認(1回にまとめる)

App Store 版 v1.0.2 の入った iPhone に TestFlight 版を上書きして:
- **夜(約20分)**: 古い日記と大切な人が残っている/ウィジェット小・中(明るい・暗い)/中のスタンプがアプリに反映される/マイク(断っても書ける)/通知の時刻を2分後にして届く/365問の下書きに印
- **翌朝(1分)**: 通知の日数が1日増え、本文が今日の問い/ウィジェットが新しい日になっている

iCloud の確認は省く(Isar は Documents、設定は Library/Preferences で、どちらもバックアップに入る。通知は起動時に入り直る)。
